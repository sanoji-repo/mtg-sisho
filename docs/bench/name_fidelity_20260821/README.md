# 名前忠実度の煙試験（2026-08-21・承認「うん、やってみよう」）

問い: 「英語 MCP があれば Claude が訳せる」は本当か。カード名は翻訳でなく固有名詞の照合——
クライアントは DB 無しで日本語の正式名をどれだけ当てられるか、MCP を挿すとどう変わるか。

## 設計
- 質問: 「このカードの日本語の正式名は？ 日本語版が無ければ『日本語版なし』、分からなければ『不明』。出力は『答え: <名前>』1 行」
- 42 問・DB から決定的抽出（seed=md5(card_name||'seed42')）: A 日本語版なし 10／B 新セット Hobbit 10／
  C 両面・当事者・分割 8／D 有名（EDHREC 上位 150）6／E 非直訳名（手選び）8
- 条件: off=Claude Sonnet 単体（`--mcp-config {} --strict-mcp-config`）／on=同＋mtg-rag MCP（stdio・`--allowedTools mcp__mtg-rag__*`）
- 実行: `claude -p --model sonnet --output-format json`・4 並列・外部課金なし（MAX 枠・notional $4.5）
- 正解: DB の japanese_name（NULL=日本語版なし）。採点は機械（正規化後の完全一致・表面名のみ一致も可・ルビ除去）
- 材料: name_questions.csv（問題）・name_results.tsv（全 84 行の答えと判定）・score_names.py・run_one.sh

- off の誤りの顔ぶれ: Cori-Steel Cutter→「剣刃、コリ=スティール」／Psychic Frog→「サイキック・フロッグ」／
  Sheoldred, the Apocalypse→「シェオルドレッド、絶望の親玉」／Skullclamp→「頭蓋骨締め」（一字違い）／

## 追試: `--effort xhigh`（方針「ベンチマークはそっちの方がよさそう」）

同じ 42 問 × 2 条件を `--effort xhigh` で再走（材料= name_results_xhigh.tsv・run_one_xhigh.sh）。

| 条件 | 既定 effort | xhigh |
|---|---|---|
| 単体 正解 | 8（19%） | **16（38%）** |
| 単体 捏造/誤り | 24 | **16** |
| 単体 不明 | 5 | 9 |
| 単体「なし」誤判定 | 5 | 1 |
| MCP 有り 正解 | 42（100%） | **42（100%）** |

- 考える量を増やすと捏造は減り「不明」が増える（謙虚になる）が、**それでも 42 問中 16 問で存在しない名前を作る**。
  有名カード 6 問中 3 問外すのは不変（Skullclamp→「スカルクランプ」・Garruk's Uprising→「ガラクの隆盛」）。
- 名前は知識の問題で推論の問題ではない、という null model はこの範囲で支持された（改善はするが解決しない）。
- 観測の注意: xhigh の単体条件で 2 問（Ezio・Achilles）がターン数 3〜6＝**既定の Web 検索道具を使った**形跡があり、
  それでも捏造した。単体条件は「記憶のみ」でなく「Claude Code の既定道具つき」である点は次回 `--disallowedTools WebSearch,WebFetch`
  で純化する。MCP 条件は全問 3 ターン（search 1 回）。

## 読み方の留保
- クライアントは Sonnet 1 種・n=42・質問が「日本語名は？」と名前を直接問う形＝MCP 条件は道具を引く動機が最大。
  会話の中で名前に言及する場面（Helm of Obedience の実例）では引かずに答える率が上がる可能性があり、それは別の試験で測る。
- 正解は DB の値。DB 側の japanese_name の誤り・欠落（残 124 枚の真正の不在含む）はこの試験では検出できない。
- 「正解」の判定は完全一致。表記ゆれ（締/絞）も誤りに数えた＝厳しめ。

## 結論（この試験の範囲で）
「Claude が訳せるから日本語 DB に価値は無い」は**否**。固有名詞は翻訳でなく照合で、単体のクライアントは 42 問中 8 問しか当てられず
24 問で存在しない名前を作った。MCP を挿すと 42/42。**この MCP の価値の置き場所は「日本語の正式名と、その不在を
正本として返すこと」**であり、数字で示せる。
